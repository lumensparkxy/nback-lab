# Feature specifications

Specifications define behavior; GitHub issues track delivery. One feature can
have several implementation issues. Changes to accepted behavior require agreement
and an updated specification in the same PR as the implementation.

`Superseded`; delivery state belongs to issues. Do not treat an agreed product
direction as approval of every detailed behavior proposed later.
